## プロジェクト概要：解決する課題と、誰のためのものか（3,000字まで）

**解決する課題**
私はこれまで、暴れる子どもを力で押さえつけたり、大声で怒鳴ったりする場面を見てきました。それは、強度行動障害のある子どもや大人にとって不幸であることはもちろん、その家族や支援者にとっても大きな不幸です。

強度行動障害とは、自傷・他害・こだわり・物壊し・睡眠の乱れなどが、ふつうでは考えられない頻度で続き、今の環境では支えるのがとても難しい状態です。医学の診断名ではなく、行政の言葉です。これは一部の特別な話ではありません。13自治体を調べた研究では、該当する人は人口10万人あたり約89人と推計されています（勝井 2025）。施設の職員から虐待を受けた人のうち、強い行動障害があるとされた人は、2014年度の135人から2021年度の346人に増えました（同）。

困っているのは、本人・家族・支援者のすべてです。
- **本人**: 問題とされる行動は、本人と環境とのかみ合わなさから生じる「訴え」と考えられています（日本行動分析学会）。言葉で伝えにくい困りごとを、行動で表しています。
- **家族**: 一人で外出や留守番ができず、長い時間の見守りが必要なことが多く、同居する家族の負担は大きいと言われています（志賀 2019）。
- **支援者**: 罰や力で抑える対応は、すぐ止まったように見えるため、人手の足りない現場ほど使われやすく、当たり前になりやすいとされています。しかし実際には、行動をさらに悪くすることがあります。一人で抱えこむと、叱るなどの誤った対応もしやすくなります（日本行動分析学会）。

国は2013年度から支援者を育てる研修を始めました（加藤 2019）。それでも、標準的な支援ができる事業所はまだ少なく、研修を受けた人が職場に戻ってチームで実践するのは簡単ではありません（志賀 2019）。家族・学校・施設で記録のしかたも見立ても人によってばらばらです。専門家がそばにいなければ、記録は「書いて終わり」になり、行動の理由を考えることも、支援の効果を確かめることもできません。

**誰のためのものか**
- **強度行動障害のある本人**: 行動の理由に合った、罰を使わない支援を、家でも学校でも施設でも、子どもから大人になっても、同じ記録を引き継いで受けられるようにします。人生のどの時期も切れ目なく支えることが求められています（志賀 2019）。
- **家族**: 専門家がそばにいなくても、記録からグラフと支援の候補が得られます。一人で抱えこまず、学校や施設と同じ記録を見て話し合えます。
- **学校の先生・施設の職員・相談員**: 場所ごとにばらばらだった記録を同じやり方にそろえ、チームで変化を確かめながら支援計画を見直せます。

**どんなアプリか**
家族・学校・施設が同じやり方で行動を記録し、グラフで変化を見られるスマホアプリです。記録がたまると、Claude が「その行動は何のために起きているのか」の仮説を立て、罰を使わない支援の候補を出します。

**作った人**
特別支援学校の教員で、公認心理師です。応用行動分析学の研究で修士号を取りました。

教員として現場で、また応用行動分析学を学んだ者として感じてきた「足りないもの」を形にしました。同じやり方で記録し、同じグラフを見て、行動のはたらきから支援を考える。その手順を、専門家がいない家庭や施設にも届けたいと考えました。

**行動分析学の手法を取り入れた理由**
日本行動分析学会のガイドラインは、罰を使わずに望ましい行動を増やし、生活の質を高めることを目的にしています。国の支援者研修も、応用行動分析を土台にした「適切行動支援」を柱の1つにしています（志賀 2019）。このアプリは、ガイドラインの支援の手順を、専門家がいない家庭や施設でも同じように回せる形にして、上の問題に答えます。
- **機能的アセスメント（行動の理由から考える）**: 支援の前に「なぜその行動をするのか」を知ることが必須とされています。ABC記録から、「注目」「要求」「回避・逃避」「感覚」のどれが当てはまりそうかを、Claude が件数と根拠つきで示します。
- **罰を使わない支援（ポジティブ行動支援）**: 先にできる環境の工夫、代わりの行動、できたときの認め方だけを提案します。
- **記録とグラフで効果を確かめる**: 回数・続いた時間・強さをグラフにし、目標と達成基準で計画→実行→評価→修正を回します。
- **チームでの支援と合意（一人で抱えこまない）**: 国の研修でも、一人の判断で動かず、チームで決めた方法を続けることが大切とされています（志賀 2019）。記録と計画をチームで共有し、家族が合意してから実施します。小さな成果は「できたこと」として自動で拾います。
- **身体拘束は治療ではない**: 3つの要件（切迫性・非代替性・一時性）の確認と、あとの検討を記録に残し、件数が多ければ計画の見直しをすすめます。

**作ったもの（ハッカソン期間中に作ったもの）**
1. **10秒で残せる記録**: 行動のボタンを押すだけで +1。続いた時間・待ち時間・強さ（3段階）も測れます。
2. **ABC記録**: 直前のこと・その後どうなったか・状況要因（睡眠不足など）を選ぶだけで書けます。
3. **インターバル記録・時間サンプリング**: 区間ごとに ○× を付ける行動分析の測り方です。
4. **グラフと ABC集計**: 回数・強さ・起きた区間の割合を折れ線で表示します。
5. **AI による機能分析の補助（Claude）**: ABC記録が10件以上たまると機能の仮説を示し、支援者が「採用」した仮説に合わせて支援の候補を出します。
6. **支援計画と合意**: 変えるたびに「何を・なぜ変えたか」が消せない履歴に残ります。
7. **身体拘束の記録**: 家族への報告も残し、保存した記録は消せません。
8. ほかに、睡眠の記録、好きなもの（強化子）、支援会議メモ、PDF レポート、CSV、お試し用のサンプル。

**AI の安全対策**
- 罰・弱化・嫌悪刺激・身体拘束・隔離・叱責・計画的無視は提案させません。禁止語が出たら捨てて作り直し、だめなら結果を出しません。
- 診断・服薬・治療方針の助言をしません。結果は「AI による仮説」と必ず表示し、採用するかどうかは支援チームが決めます。
- 名前を「対象者」「支援者A」などに置きかえて送ります。写真は送りません。

## 使用した Claude の製品・機能

フォームの選択肢から、当てはまるものをすべて選ぶ。選ぶときの材料:

- **Claude Code**: 仕様書づくりから、画面・データ・AI 部分の実装、ブラウザでの動作確認、公開の設定まで、Claude Code と一緒に進めました。発注者（作者）が決めたことと Claude の提案を仕様書で分け、決まったことだけを作りました。
- **Claude API（Sonnet 5.5）**: アプリの中の機能分析の補助と、ABC集計のまとめに使っています。サーバー側（Cloudflare Pages Functions）からだけ呼び、API キーは画面側に置いていません。
- **構造化出力**: 結果を JSON スキーマで受け取り、カードで表示します。
