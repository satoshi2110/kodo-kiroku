## プロンプト本文

あなたは、ハッカソンの審査員として1日に何本も紹介動画を見ている、UI・映像デザイナーです。このアプリ（強度行動障害の支援記録・共有アプリ「行動記録」）の画面を、**審査員が動画の数秒で「やさしく、安心して使える」と感じる**ところまで磨いてください。そのあと、動画（`docs/提出/デモ動画_v6.mp4`）の画面の部分を撮り直します。

### 0. 始める前に（戻せるようにする）
1. 今の状態を残します。発注者に聞いてから、今の変更をコミットし、タグ `before-ui-polish` を付けます。
   - `git add -A` は使わない。ファイルを1つずつ選ぶ。特に、名前にキーが入っている `.envsk_aec1…` は絶対に入れない（先にファイル名を直すか消すよう発注者に伝える）。`.codex/`・`ios/` などは入れるか聞く。
2. 新しいブランチ `feature/ui-polish` で作業します。戻すときは `git switch feature/supabase-login`（またはタグ）で戻れることを、最初に発注者に伝えます。
3. 動画 v6 とその素材は消さず、上書きもしない。新しいものは v7 として別に作る。

### 1. 守ること（変えないもの）
- `CLAUDE.md` と `docs/仕様書.md` に従う。**変えてよいのは見た目と画面の並べ方だけ**。記録の中身・データの形・RLS・同期・AI の安全対策・暗号化・監査ログには触らない。仕様にない機能は足さない。
- 画面の文はすべて日本語。言い回しを変えるときは、意味が仕様とずれないか確かめる。
- スマホ幅 390px が基準。主要ボタン 48px 以上、補助ボタン 24px（タップ範囲 32px）以上。
- 文字と背景の濃さの差（コントラスト）は WCAG AA（本文 4.5:1、大きな文字 3:1）以上。色だけで意味を伝えない（形・文字も添える）。
- 「問題行動」と「できたこと／代わりの行動」は、色で見分けられるまま残す。ただし問題行動の色は、責める・怖がらせる感じにしない。
- 端末の「動きを減らす」設定（prefers-reduced-motion）では動きを止める。
- オフラインでも同じ見た目で動く（PWA）。書体や画像を外から読み込む場合も同梱する。

### 2. 進め方
1. **今の画面を見て診断する**: dev サーバー（`.claude/launch.json` の dev、port 5173）を開き、サンプルのデータで全画面を 390px で見て、スクリーンショットを撮る。審査員の目で「動画で数秒しか映らないときに、何が伝わらないか」を画面ごとに3つまで書き出し、優先順位を付けて発注者に見せる。
2. **デザインの土台（デザインの決まりごと）を作る**: 色・文字の大きさの段階・余白の段階・角の丸み・影・アイコンの太さ・動きの速さを、`src/styles.css` の `:root` の値（トークン）としてまとめる。画面ごとにばらばらな値は、このトークンに置きかえる。
3. **色の案を3つ作って選んでもらう**: たとえば「やわらかい緑と生成り（動画の保護者の緑とつながる）」「落ち着いた青緑」「やわらかくした今の青」。それぞれホーム・ABC記録・グラフ・AI の提案の4画面に当てた見本（スクリーンショット並べ）を見せて、発注者が選ぶ。選ぶまで画面全体には広げない。
4. **書体**: おすすめは、見出し・大きなボタン・数字に丸みのある書体（例: Zen Maru Gothic や M PLUS Rounded 1c。`@fontsource` で同梱し、使う太さだけ入れる）、本文は端末標準の書体（軽く読みやすい）。読み込みが遅くならないか、オフラインで出るかを確かめる。別の案がよければ理由を添えて出す。
5. **画面を磨く（この順で、1画面できるごとにブラウザで確かめて見せる）**:
   1. ホーム（最初の印象。「ボタン1回で記録」が一目で分かること。できたこと・申し送りはあたたかく）
   2. ABC記録（落ち着いたあとに迷わず選べること。選んだものがはっきり分かること）
   3. グラフ（ベースラインと支援開始の線、減っていく様子が、小さく映っても読めること。ABC集計も同じ見た目に）
   4. AI の提案（仮説の「どのくらい当てはまりそうか」と根拠が読みやすいこと。「決めるのはチーム」と「採用」がはっきりしていること）
   5. 残りの画面（好きなもの・支援計画・できたこと・チーム・設定・ログインなど）に同じ決まりごとを広げて、統一感を出す
6. **動きは控えめに**: 記録できたときの小さな合図、画面の切りかえ、グラフが伸びる動きなど。0.2〜0.3秒ほどで、はねすぎない。動画で映える所を優先する。
7. **確かめる**: 型チェックとテスト（`npm run build`、テストがあれば `npm test`）が通ること。390px と広い画面、ダーク表示がある場合はそれも見る。最後に、変える前と後のスクリーンショットを画面ごとに並べて発注者に見せる。
