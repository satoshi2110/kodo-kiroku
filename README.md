# 行動記録（強度行動障害 支援記録・共有アプリ）

強度行動障害のある人を支える家族・学校・施設の人が、**同じやり方で行動を記録し、グラフで変化を見て、チームで共有する**ためのスマホ向けアプリ（PWA）です。
記録がたまると、AI（Claude）が ABC記録から「行動のはたらき（機能）」の仮説を立て、罰を使わない支援の候補を出します。採用するかどうかは支援者が決めます。

「Built with Claude: Japan 2026」ハッカソンの作品です。

## 試し方（審査の方へ）

1. 公開ページを開きます: **https://kodo-kiroku.pages.dev**
   - スマホで開くのがおすすめです（画面は幅 390px を基準に作っています）。パソコンでも動きます。
2. 最初の画面で「内容を読み、同意します」にチェックを入れ、**「サンプルで試す」** を押します。
   - 架空の対象者「サンプルさん」と、3週間分の記録・支援計画・支援会議メモが、この端末の中だけに作られます。実在の人のデータではありません。
3. 試せること
   - **ホーム**: 行動のボタンを押すと +1。右上の赤い「−1」で取り消し。「頭たたき」は強度を選ぶシートが出ます。記録の行を押すと ABC（前後のようす）を詳しく書けます。
   - **大きな声を出す**（インターバル記録）: 10秒ごとの区間で ○×を付けます。区間が終わると画面の枠が光り「記録してください」と出ます。
   - **睡眠**: ホームの「睡眠（昨夜）」から、寝た時刻・起きた時刻を入れます。いつもより2時間以上短い夜はオレンジになり、その日の ABC記録には「睡眠不足」が最初から付きます。
   - **グラフ**: 行動ごとの回数・強度・起きた区間の割合。日・週・月を切りかえられ、縦のパネルは一緒に横へスクロールします。縦の点線が「支援開始」「計画の変更」、横の点線が支援計画の目標です。上のタブで「時間帯」（30分ごとの図）と「ABC集計」（直前のこと・その後どうなったか・状況要因などの件数）に切りかえます。
   - **計画**（下のタブ）: 支援計画。標的の行動・機能の仮説・目標と達成基準・先にできる工夫などを書き、保存すると変更の履歴に残ります。合意をお願いした人が確認し、家族（管理者）が合意した日から「実施中」になってグラフに線が入ります。ここから「支援会議メモ」（会議の日のグラフを残す）、「できたこと」の一覧、「身体拘束の記録」（消せない記録と見直しの目安）、「PDF レポート」（印刷画面から PDF に保存）を開けます。
   - **場所**: ホーム上部の「場所」を押して、いまの場所（自宅・施設・学校）を選びます。記録には場所の名前だけが付きます。「場所の登録・編集」で「いまここを登録」もできます（位置はこの端末の中で照らし合わせるだけで、保存も送信もしません）。「住所で探す」では、入力した住所の文字だけを国土地理院に送って中心を探し、地図のピンで直せます。
   - **好きなもの**（強化子リスト）: ホーム右上の「好きなもの」。写真を撮って追加し、ハマり度を ● で直せます。
   - **行動**: ホーム右上の「行動」で、行動の追加・編集・非表示ができます。
   - **さかのぼって入力**: ホームの「今日の記録」の下。日時を指定して記録を足したり、自動で 0 になった日を「観察していなかった」に直したりできます。
   - **書き出し**: 「チーム」→「同意と設定」の「データ」で、記録・ABC・睡眠を Excel で開けるファイルにできます。
   - **AI**: 「チーム」→「同意と設定」で「AI を『あり』にする」→ 同意 → 下に出る「AI」タブ →「AI で分析する」。仮説を「採用」すると、代わりの行動や先にできる工夫の提案を受けられます。AI ありのときは、ABC集計の画面で集計を短い文にする「AI のまとめ」も使えます（機能の判断や支援の方法は書きません）。

データはすべてブラウザの中（IndexedDB）に保存されます。AI を使ったときだけ、名前を置きかえた記録（下記）をサーバー経由で Claude に送ります。

## AI まわりの安全対策

- **仮名化**: 対象者は「対象者」、支援者は「支援者A・B…」、場所は「場所A…」に置きかえ、関わった人は所属（家族・施設の職員など）だけを送ります。写真は送りません。期間は直近4週間・最大200件。
- **出しすぎない**: ABC記録が10件未満なら AI を呼ばず「データ不足」と表示します。
- **出してはいけないもの**: 罰・弱化・嫌悪刺激・身体拘束・隔離・叱責・計画的無視は提案しません。診断・服薬・治療方針の助言もしません。プロンプトで禁じたうえで、出力に禁止語があれば捨てて1回だけ作り直し、それでもだめなら結果を出しません。
- **AI のまとめ**: 送るのは件数の集計だけです。300字を超えたり、機能の判断・助言にあたる語（「回避」「すべき」など）が入ったりしたら捨てて作り直します。
- **身体拘束**: AI は身体拘束を提案しません。身体拘束の記録は AI に送りません。
- **構造化出力**: 結果は JSON スキーマで受け取り、カードで表示します。自由文のままは出しません。
- **キーの置き場所**: Anthropic の API キーはサーバー側（Cloudflare の暗号化された環境変数）だけに置き、画面のコードには入れません。
- **回数の上限**: 公開ページ（ログインなし）では、サイト全体の1日の上限（30回）と、1人あたりの回数（端末側で数えます）があります。チームで共有する版（ログインあり）では、1人・チーム・アプリ全体の回数をサーバーで数え、AI を呼ぶ前に止めます。

使うモデルは `claude-sonnet-5-5` です（`functions/api/ai.ts`）。混み合って使えないときは、Anthropic 側で別のモデルに切りかえて答える設定（fallbacks）にしています。答えたモデルの名前は結果と一緒に保存します。

## 作り

- 画面: React 18 + TypeScript + Vite、PWA（vite-plugin-pwa）。保存は Dexie（IndexedDB）。グラフは外部ライブラリを使わない自前の SVG。場所の地図は Leaflet と国土地理院の地理院タイル。
- AI のサーバー側: Cloudflare Pages Functions（`functions/api/ai.ts`）と `@anthropic-ai/sdk`。画面からは `src/ai/adapter.ts` だけを通して呼びます。
- 仕様書: `docs/仕様書.md`、ワイヤーフレーム: `docs/wireframes/`。
- チームでの共有: Supabase（ログイン・同期・行レベルセキュリティ）。表の作り方は `supabase/migrations/`、他のチームのデータを読めない・書けないことの確かめは `supabase/tests/rls.sql`。

## 手元で動かす

```bash
npm install
npm run dev
```

http://localhost:5173 で開きます。手元では AI は見本の結果（「（見本）」と表示）を返し、外には何も送りません。
`.env` がなければ、公開ページと同じ「端末の中だけ」の版で動きます。`.env` に Supabase の値を書くと、ログインとチームでの共有がある版になります（下の「チームで共有する版」）。

本物の AI を手元で試すときは、`.dev.vars` というファイルに `ANTHROPIC_API_KEY=...` を書いて（git には入りません）、次を実行します。チームで共有する版では `SUPABASE_URL=...`、`SUPABASE_ANON_KEY=...`（`.env` の Supabase の2つと同じ値）も書きます。そのときの AI は、ログインしてチームに入った人だけが使えます。

```bash
npm run pages:dev
```

## 公開のしかた（Cloudflare Pages）

1. Cloudflare の Workers & Pages → 作成 → Pages → Git に接続して、このリポジトリを選ぶ。
2. ビルドの設定: フレームワークは「なし」、ビルドコマンド `npm run build`、出力ディレクトリ `dist`。
3. 設定 → 環境変数に `ANTHROPIC_API_KEY` を **暗号化** して追加する。
4. サイト全体の1日の上限: KV 名前空間を作り、`AI_USAGE` という名前でバインドする。上限は環境変数 `AI_DAILY_LIMIT`（既定 30）。
   - 公開ページ（端末の中だけの版）では **必須** です。これがないと AI は動きません（ログインなしで呼べるため）。
5. チームで共有する版として公開するときだけ、次も追加する。
   - ビルド用: `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`（画面に入ってよい値）。
   - AI のサーバー用: `SUPABASE_URL`、`SUPABASE_ANON_KEY`（同じ値。AI を呼べる人と回数をサーバーで確かめる）。
   - service_role key はどこにも入れません。

## チームで共有する版（ログインあり）

1. Supabase のプロジェクトを作り、SQL Editor で `supabase/migrations/` の 0001〜0024 を番号の順に流します。0014 から、招待コードか開始コードがないとアカウントを作れません（Supabase の管理画面の「Add user」でも作れなくなります）。0020 から、管理者・副管理者・支援リーダーは7日のうちに多要素認証（認証アプリ）を設定しないと、閲覧だけになります（チームの基準は「同意と設定」で変えられます）。
2. `supabase/tests/rls.sql` を流して、すべて合格することを確かめます（他のチームのデータを読めない・書けない、など）。
3. `.env.example` を `.env` にコピーして、Supabase の URL と anon key を書きます。
4. 新しいチームを作るには「開始コード」が要ります。ほかのメンバーは、管理者が出す「招待コード」で入り、管理者が承認します。
5. 管理者を代わるときは、チーム画面の「管理者の引き継ぎ」を使います。管理者が副管理者か「家族」の印の人に頼んで相手が受けるか、管理者が操作できないときは副管理者が申し込み、14日のあいだ断られなければ入れかわります。
6. AI は初めは「なし」です。管理者がチームの設定で同意すると「あり」になり、「同意を取り消して『なし』に戻す」で同意を取り消せます。

いまは Supabase 標準のメール送信を使っているため、確認やパスワード再設定のメールは英語で、届く相手にも制限があります。実際に使い始める前に、自分のメール送信（SMTP）に切りかえます（日本語の文面は `supabase/email-templates/`）。
